1Motivation

Ruffle's XML type (the mutable E4X type) models every node as its own Gc object — an E4XNode — wired into a parent/child graph and carrying change-notification machinery for data binding.

For large, never-mutated documents — data providers with 100k+ rows, e.g. a measured workload of ~250,000 rows — that per-node overhead, and the garbage-collector tracing it implies, is the dominant memory cost. Yet once the document is parsed none of that flexibility is needed: the document is read-only.

XMLReadOnly is an immutable parallel to XML: parsed once into a compact arena, never mutated, emitting no notifications. It supports the full E4X read syntax (.child, ..desc, @attr, for each, .() filtering) through native dispatch, and navigation returns real XMLList values whose elements are XMLReadOnly — so is XMLList holds and results feed straight into the usual list data-provider pipeline.

Net result On the ~250k-row workload: live total 670 MB → 449 MB (−33%), node record 36 B → 28 B, node count 10.77M → 5.50M — at parity of rendering and of the E4X read API.

2Architecture: O(1) GC tracing

The key architectural insight: a read-only tree cannot contain cycles. That lets the store be represented as pure owned Rust data (Vecs of records + a string pool) inside a single Gc, marked #[collect(require_static)]. To gc-arena that Gc is an opaque unit, so GC tracing becomes O(1) regardless of node count, instead of O(nodes) as for the mutable XML node graph.

This also sidesteps the synchronous-System.gc() / gc-arena pacing pressure that large mutable XML graphs create: with no millions of Gc nodes to collect, the document itself generates no collection pressure.

3Chunked arena & logical indices

The store uses two chunked arenas: one for node records (Vec<Box<[E4XNodeDataReadOnly]>>, 65,536 records per chunk) and one for string bytes (Vec<Box<[u8]>>, 1 MiB chunks). Chunking eliminates copy-on-grow: a single contiguous Vec would reallocate and relocate everything as it grows; fixed chunks are never moved.

As a consequence every reference is a logical u32 index, not a pointer: the high bits select the chunk, the low bits the in-chunk offset. This is crucial for 64-bit robustness (see §9): crossing the 4 GB boundary does not break indexing, because each access does as usize and widens on its own.

4The node record (28 bytes)

Each node is a fixed-size 28-byte record — seven u32 fields — locked at compile time by const _: () = assert!(size_of::<E4XNodeDataReadOnly>() == 28). Two fields are packed to save bytes without depending on the XML shape: kind_parent (node kind + parent index) and value_or_child (a tagged union).

FieldMeaning
kind_parenthigh 3 bits = node kind (Element/Text/Attribute/Comment/PI); low 29 bits = parent index (PARENT_NONE at the root)
namelocal-name reference into the string arena
value_or_childunion: empty / first-child index (bit 31 = 1) / value reference (bit 31 = 0)
ns / prefixnamespace-URI and prefix references (string arena)
next_siblingnext sibling index (children form a singly-linked list)
first_attrfirst attribute index (attributes are nodes in the arena)

5Byte-level optimizations

Three cumulative optimizations, all shape-safe (they do not depend on the particular XML shape): they never regress versus the base case, whatever the content.

5.1 — Single-child-text collapse

An element whose only child is text stores no separate Text node: the text goes inline in the element's value field. The child Text node is synthesized on demand when requested, by tagging the index with the VIRTUAL_TEXT flag (bit 31). Records are Copy and the string is real in the arena, so the virtual identity is stable (===, parent(), childIndex() all consistent). Mixed or multiple content → flushed as a real node → behavior identical to before.

5.2 — Kind packing

The node kind (3 bits) is packed into the high bits of the parent index, fusing two fields into kind_parent. The index space stays 29 bits (PARENT_NONE = 0x1FFF_FFFF as the root sentinel). Record 36 → 32 B.

5.3 — value / first_child union

value and first_child share the value_or_child slot: NO_NODE = empty; bit 31 (CHILD_FLAG) set → first-child index; otherwise → value reference. No check on kind is needed: the flag disambiguates on its own. Mutual exclusion is guaranteed by the collapse invariant (an element receives a value only if first_child == NO_NODE; non-elements have no children), not by the data. Record 32 → 28 B.

6Polyglot XMLList & the is XML masquerade

XMLList is made polyglot: its elements can be mutable XML (E4XNode) or XMLReadOnly, modeled by the enum E4XOrXml { Xml(…), ReadOnly(…) }. The E4X operators (getproperty/getdescendants/for each) dispatch through TObject trait methods, so the new type receives the syntax via the existing path — the class can live in any package.

XMLReadOnly does not extend XML (which is final): it still reports is XML == true through a runtime masquerade, so framework code that branches on node is XML keeps working. This is an AS3-level type-operator lie only — the Rust downcast as_xml_object() stays None, so Ruffle internals still tell read-only nodes apart (no mutation, no raw E4XNode access). The mutation API exists on the surface but is an inert no-op, and no change notifications are ever emitted.

7Native sortKeyed

Read-only providers are commonly fed to data grids and list controls. A framework's column sort decorates each row by reading E4X fields through the generic path, allocating a throwaway XMLList per access; on large grids that comparison-time allocation dominates. XMLReadOnly.sortKeyed(...) moves the whole sort into Rust: 

public static native function sortKeyed(
    items:Array, fields:Array, kinds:Array, descending:Array):Boolean;

//  fields[j]:  ""=the node itself · "@n"=attribute n · "n"=child element n
//  kinds[j] :  0=string · 1=numeric · 2=lowercased string
//  → true once sorted; false if the rows aren't all XMLReadOnly (caller falls back)

8Memory dynamics under synchronous sorting

Sorting a large provider through the framework's generic path reads each row's E4X fields, and every read materializes a transient XmlListObject graph (a Gc allocation). During a synchronous AS3 call the garbage collector cannot run — gc-arena needs &mut Arena, which is unavailable while AVM2 code is executing — so these transient objects accumulate for the entire duration of the sort, a large temporary spike proportional to rows × comparisons.

Takeaway The spike is a property of synchronous execution under an incremental collector, independent of the underlying allocator. Two complementary levers reduce it: (1) sort natively via sortKeyed (no per-access materialization); (2) on the caller side, extract sort keys once into a flat array so the transient graphs are never built.

9wasm64 & encoding caps

The u32 references are logical indices, not addresses: crossing the 4 GB linear-memory boundary does not break indexing. The capacity limits come solely from the bit encoding:

FieldEncodingCap
parent29 bits in kind_parent536M nodes (~15 GB)
node indexbit 31 = VIRTUAL_TEXT/CHILD_FLAG< 2³¹ nodes
string refchunk « 20 (12-bit chunk)2 GiB/store *

* the chunk encoding would allow 4 GiB/store, but the union narrows it to 2 GiB: a value reference in value_or_child must keep bit 31 clear ⇒ chunk < 2048.

For the real workload (~250k rows → 5.5M nodes, ~20 MB of strings) every cap is over 100× away: the encoding is not a practical constraint.

10Application integration

The class is registered by Ruffle as top-level ("", "XMLReadOnly") — it is not in the SDK playerglobal.swc. The host references it dynamically, so no compile-time declaration is needed: 

var XMLReadOnlyClass:Class = getDefinitionByName("XMLReadOnly") as Class;
var ro:* = new XMLReadOnlyClass(rawXmlString);
if (obj is XMLReadOnlyClass) { /* … */ }

The memory saving is realized by constructing XMLReadOnly directly from the data source's raw string payload instead of materializing a mutable XML tree. Because the type masquerades as XML (is XML true) yet stays immutable and emits no notifications, it slots into the existing data-provider flows that expect XML while remaining read-only.

Decoding straight to XMLReadOnly (SOAP / WebService)

The getDefinitionByName path above still constructs XMLReadOnly from a string you already hold. The most effective integration pushes the conversion to the earliest point — the SOAP decode — so a mutable tree is never built at all. The standard RPC stack has a WebService drive a SOAPDecoder that turns the incoming envelope into mutable XML (or an object graph). By subclassing both WebService and SOAPDecoder and overriding the decode step, the relevant response body is wrapped as XMLReadOnly directly from the raw response XML, bypassing mutable E4X materialization entirely.

The win is twofold: the compact store is built once, at parse time, and the large transient mutable tree — which the default decoder builds and then immediately discards — is never created, so even its build-then-free peak disappears.

A minimal sketch — a decoder that adds the format, a service that installs it, and the call site:

1 · A SOAPDecoder subclass adding the "e4xro" format

import mx.rpc.soap.SOAPDecoder;
import mx.rpc.soap.SOAPResult;
import flash.utils.getDefinitionByName;

// "e4xro": parse the whole SOAP envelope once into the compact read-only
// arena (XMLReadOnly) instead of a heavy mutable XML tree. event.result
// becomes the SOAP Body children — an XMLList of XMLReadOnly elements —
// a drop-in for the stock "e4x" format.
class ReadOnlySOAPDecoder extends SOAPDecoder {

    private static var roClass:Class =
        getDefinitionByName("XMLReadOnly") as Class;

    override public function decodeResponse(response:*):SOAPResult {
        // Anything other than "e4xro" decodes as usual.
        if (resultFormat != "e4xro")
            return super.decodeResponse(response);

        var xml:String = (response is XML)
            ? XML(response).toXMLString()
            : String(response);

        var ro:* = new roClass(xml);          // parse into the arena

        var result:SOAPResult = new SOAPResult();
        var body:* = ro.*::Body[0];           // SOAP Body, any namespace
        var fault:* = body.*::Fault;          // SOAP Fault, any namespace
        if (fault != null && fault.length() > 0) {
            result.isFault = true;
            result.result  = fault;
        } else {
            result.result  = body.children(); // like "e4x": Body children
        }
        return result;
    }
}

2 · A WebService subclass that installs the decoder on every operation

import mx.rpc.AbstractOperation;
import mx.rpc.soap.mxml.Operation;
import mx.rpc.soap.mxml.WebService;

dynamic class ReadOnlyWebService extends WebService {
    override public function getOperation(name:String):AbstractOperation {
        var op:AbstractOperation = super.getOperation(name);
        var soapOp:Operation = op as Operation;
        if (soapOp != null && !(soapOp.decoder is ReadOnlySOAPDecoder))
            soapOp.decoder = new ReadOnlySOAPDecoder();
        return op;
    }
}

3 · Opt in per operation

var ws:ReadOnlyWebService = new ReadOnlyWebService();
ws.loadWSDL(wsdlUrl);

var op:AbstractOperation = ws.getOperation("getRows");
op.resultFormat = "e4xro";                    // read-only decoding
op.addEventListener(ResultEvent.RESULT, onResult);
op.send(args);

// In onResult, event.result is an XMLList of XMLReadOnly elements,
// ready to feed a list/grid data provider.
